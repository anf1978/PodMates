# Claude workspace hooks

Requires Node 22+ and `npm ci`. Start Claude Code at the repository root and trust
the committed project settings. Hook commands use a repository-relative path, so they work in both POSIX shells
and Windows `cmd.exe`; file processing itself uses Node, not shell interpolation.
Restart the session after changing hooks so its loaded configuration is current.

`workspace.mjs` reads a Claude hook event as JSON on stdin. `protect` rejects
generated paths, existing `// GENERATED` headers (first five lines), new generated
Write content and paths outside this project. Header detection supplements path
permissions because permission globs cannot inspect contents. Agents that edit
with `apply_patch` (for example Codex loading these settings) send a patch instead
of `file_path`; the hook reads every `Add`/`Update`/`Delete`/`Move to` file from the
patch headers and applies the same checks to each. Copilot CLI instead sends `path`
with `file_text` (create) or `new_str` (edit), which the hook also understands. `format` runs the
locally installed Prettier then ESLint with `--fix` on each edited file; ignored or
unsupported files follow existing tool configuration. `index.html` and generated
files are never formatted. `check` runs `npm run check` on every Stop, including a
retry after failure. Exit 2 reports failures and blocks a successful Stop.

These are editing guardrails, not a security sandbox: shell commands, pipelines
and hook scripts can write files. Do not use the command allow-list to bypass them.
Keep new generated artifacts under the denied paths and include their header.

## Verification

`npx vitest run tests/workspace-hooks.test.ts` exercises real hook processes with
Claude-shaped stdin, including formatting/lint fixes and failed Stop checks.
`npm run check` includes those tests. No Claude account is needed for this check.

For an actual Claude Code session after `npm ci`:

1. Use Edit/Write to create a temporary TypeScript file with unformatted code and
   an ESLint-fixable issue; confirm both tools run and the file is corrected.
2. Try editing `public/data/hook-probe.json`, then an existing temporary file whose
   first line is `// GENERATED by a test`; both must be denied before mutation.
3. Make a surgical `index.html` edit only if required by a real task; confirm no
   formatter runs and the diff contains only the intended lines.
4. Finish a turn: confirm Stop runs `npm run check`. Introduce a temporary failing
   test, finish again and confirm Stop blocks; fix it and retry successfully.
5. Remove only the temporary probe files and inspect `git diff` before committing.

The automated checks exercise the handlers, not Claude's settings loader or
permission UI; use the steps above when verifying that integration.
